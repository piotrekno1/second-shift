# SecondShift 0.1.0b3

This beta redesigns the dashboard, lets a job read its own earlier reports, and
fixes a security issue with outbound requests. It also tightens sandbox memory
limits.

## Security update

Outbound requests now refuse link-local addresses (`169.254.0.0/16` and
`fe80::/10`), including the cloud metadata address. This holds even when local
addresses are allowed. Numeric forms such as decimal, hex, short IPv4 and
IPv4-mapped IPv6 are refused too, as are host names that resolve to a
link-local address. The check runs when a connection is saved and again when it
connects (#77). Upgrade beta 2 installations, especially on cloud hosts.

## Sandbox memory

The sandbox memory limit was too loose. Docker allowed a sandbox to swap as much
again as its memory limit, so a `2g` sandbox could use 4 GiB. Swap is now off.
When a sandbox runs out of memory under gVisor, the run fails with "The sandbox
ran out of memory." instead of leaving a dead session (#44).

## Included

- **Run history.** A job can set `history: N` in `.secondshift.yaml`. Each run
  then starts with that job's last N successful reports. Two optional server
  settings set the limits: `SECONDSHIFT_JOB_HISTORY_MAX` (default 5) and
  `SECONDSHIFT_RUN_HISTORY_MAX_CHARS` (default 65,536). See
  [run history](https://github.com/piotrekno1/second-shift/blob/main/docs/repository-configuration.md#run-history) (#66).
- **GitHub Actions.** The built-in GitHub connection reads Actions runs and job
  logs. The CI failures example uses it (#69).
- **Dashboard redesign.** Layered greys, line icons, a grouped sidebar with
  live status, compact lists, and an overview that compares this week with
  last week. Sign-in pages and the Django admin use the same palette.
- **Plainer errors.** Failed runs say what to do and link to the fix. Invalid
  `.secondshift.yaml` files and form errors read as plain sentences. Run buttons
  warn while the model key is broken. Unknown addresses show a not-found page.
- **Phones.** Larger buttons and 16px fields, so phones do not zoom in on forms.
- **Backup, restore and update.** The deployment guide has tested commands for
  them. A new end-to-end test checks the guide on a gVisor host (#45).

## Upgrade compatibility

From beta 2 or beta 1, keep your existing data, private configuration and
encryption keys. Install the new wheel or update the pinned container image to
`ghcr.io/piotrekno1/second-shift:0.1.0b3`. Then run the normal migration
commands. This release adds one migration, `jobs.0002_job_history`. It adds a
column with a default, so existing jobs are unchanged.

The production end-to-end test deployed beta 2, upgraded it to this release,
then restarted, backed up and restored it onto a wiped server.

**From older alpha builds, fresh databases are still required.** Follow the
[beta 1 upgrade instructions](https://github.com/piotrekno1/second-shift/blob/main/docs/releases/0.1.0b1.md).

## Limitations

The test uses stand-ins for GitHub, the model provider and S3. Real GitHub.com
and model providers, public HTTPS certificates, and production S3 permissions
still need checking on your own deployment. See the
[deployment guide](https://github.com/piotrekno1/second-shift/blob/main/docs/production-deployment.md).
