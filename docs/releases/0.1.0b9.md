# SecondShift 0.1.0b9

This beta simplifies first-run setup and fixes workspace tools in subscription
runs. It also raises the default tool-call budget and improves dashboard
navigation.

## Setup and dashboard

- Overview shows the setup checklist until the first run. The first-run step has
  one instruction and one button; a coding agent is available as optional help
  during setup and from the account menu afterwards.
- People without owner access can see who can finish the model and GitHub setup
  steps. GitHub App and personal access token instructions explain which option
  to choose and what permissions are needed.
- API token creation opens with its explanation and confirmation. The account
  menu groups token management with the optional coding-agent setup.
- Sidebar notes explain Jobs and Models, and an empty Jobs page no longer shows
  a model warning. Run activity is compact, with a separate link for each run.
- Job and run detail pages keep wide content within their grids.

## Run fixes and limits

- Subscription runs can use workspace tools through the gateway. Codex waits
  for the tool broker to start and fails if it cannot connect, rather than
  continuing without tools.
- The default tool-call limit rises from 64 to 150. Owners can raise it to 200
  without changing server configuration. Existing workspace and job overrides
  still apply. Calls to connected services count towards this limit alongside
  file reads, searches and commands.
- Reporting timestamps use UTC with whole seconds, so services such as Grafana
  can accept timestamps copied into tool arguments.

## Upgrade from beta 8

Keep your data, private environment files and encryption keys. Install the new
wheel or pin `ghcr.io/piotrekno1/second-shift:0.1.0b9`, then follow the normal
[upgrade procedure](../production-deployment.md#update-and-back-up). This release adds
no database migrations. Wait for container publishing to finish before pulling
the image. Beta releases do not advance the stable `latest` tag.

**Subscription installations need a configuration update.** Copy
`SECONDSHIFT_RUNNER_SERVICE_URL` and `SECONDSHIFT_RUNNER_SERVICE_TOKEN` from
`worker.env` into `gateway.env`, retaining their existing values. These lines
were absent from gateway files generated by beta 8 and earlier. Recreate the
gateway with `dc up -d` after updating its environment. See
[subscription setup](../production-deployment.md#optional-subscription-agents)
for the commands. Without these settings, workspace tool calls fail with
"The approved tool could not complete."

Rebuild the separate subscription agent image from this release and update
`AGENT_IMAGE` to use it. Keep the old image until active runs finish. The
application release does not publish this image. Verify a subscription run that
reads a repository file and, if used, a webhook run that calls `trigger_payload`.
Existing installations with explicit tool-call defaults or ceilings keep those
values; update them if you want the new budgets.

For older alpha installations, follow the
[beta 1 upgrade instructions](0.1.0b1.md); fresh databases are still required.

## Validation scope

Automated tests use stand-ins for external services. Real subscription logins,
provider access, public HTTPS and production storage permissions require checks
on the target deployment. The release workflow builds and checks the wheel,
runs an installed-wheel smoke test, then publishes the prerelease and container.
