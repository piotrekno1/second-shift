# SecondShift 0.1.0b4

This beta adds an MCP server, so coding agents can read jobs, runs and reports,
start approved jobs and check a `.secondshift.yaml` before it is committed. It
also changes how runs get their files. The runner no longer stores
repositories. It also shows a job's skill before you run it, and shows what a
webhook will receive.

## MCP server and API tokens

SecondShift serves an MCP server at `/mcp` over Streamable HTTP. Clients
authenticate with an API token. Create one from the account menu under
**API tokens**. The page gives a ready setup command for Claude Code.

- A token belongs to one person and works in one workspace.
- `read` tokens can use every read and manifest tool. `run` tokens can also
  start runs and sync repositories. Only admins and owners can create `run`
  tokens.
- Access is checked against the creator's current role on every request.
- Owner actions are never available to a token. These include approvals,
  connections, secrets, model providers, limits and members.
- Only a hash of each token is stored. Tokens start with `ss_` so secret
  scanners can find leaked ones.

See the [MCP guide](https://github.com/piotrekno1/second-shift/blob/main/docs/mcp.md) (#97, #99, #100, #102 to #106).

## Runs get a snapshot of their commit

Each sync used to send the runner the branch's full history, and the runner
never removed any of it. Its disk grew with every sync. Now the control plane
builds a snapshot of the run's commit and uploads it when the run starts. The
runner deletes it an hour after its last use (#116).

- Web and worker keep a Git mirror of each repository and a cache of
  snapshots. Both are caches. A missing commit is fetched from GitHub again.
- `SECONDSHIFT_SOURCE_CACHE_MAX_BYTES` limits the snapshot cache. The default
  is 2 GiB. `SECONDSHIFT_SOURCE_CACHE_ROOT` moves it.
- A repository's `.gitattributes` can no longer hide or change files in a run.
- A rerun of a commit that a force push removed from GitHub can fail once the
  cache no longer has it.

## Included

- **Skill preview.** The job page shows the skill from the synced commit as
  Markdown or raw text, with a link to the file on GitHub. The access review
  links to it. Jobs synced before this release show the skill after their
  next sync (#108).
- **Webhook preview.** The webhook form shows a sample of what gets sent and
  what never is. The Connections page shows each webhook's last delivery and
  says what is wrong and where to fix it (#109).
- **One run at a time.** Run now refuses while the job already has a queued or
  running run, and opens that run instead. Scheduled runs are unchanged (#101).
- **Shared cache.** Sign-in rate limits were counted per process and reset on
  restart. The cache is now a table in the application database by default.
  Set `SECONDSHIFT_CACHE_URL` to use Redis instead. Production refuses
  per-process caches (#98).
- **Plainer words.** The dashboard says "binding" everywhere, the same as the
  `binding:` key in `.secondshift.yaml` (#107).
- **Faster streaming.** Model responses with very long events no longer slow
  down the gateway. A benchmark suite guards these paths (#114).

## Upgrade compatibility

From beta 3, keep your existing data, private configuration and encryption
keys. Install the new wheel or update the pinned container image to
`ghcr.io/piotrekno1/second-shift:0.1.0b4`. Then run the normal migration
commands. This release adds four migrations: `jobs.0003_job_skill_text`,
`mcp_server.0001_initial`, `workspaces.0002_api_token` and
`runner.0002_session_source_sha256`. They add new tables and columns with defaults,
so existing data is unchanged. Migrating also creates the cache table.

The runner no longer reads `SECONDSHIFT_RUNNER_REPOSITORY_ROOT`. Remove it
from your configuration if you set it. After upgrading, you can delete
`RUNNER_ROOT/repositories` to free its disk. Nothing deletes it for you.

The production end-to-end test deployed beta 3, upgraded it to this release,
then restarted, backed up and restored it onto a wiped server. The release
smoke test now also uses the MCP server with read and run tokens.

**From older alpha builds, fresh databases are still required.** Follow the
[beta 1 upgrade instructions](https://github.com/piotrekno1/second-shift/blob/main/docs/releases/0.1.0b1.md).

## Limitations

The tests use stand-ins for GitHub, the model provider and S3. Real GitHub.com
and model providers, public HTTPS certificates, and production S3 permissions
still need checking on your own deployment. See the
[deployment guide](https://github.com/piotrekno1/second-shift/blob/main/docs/production-deployment.md).
