# SecondShift 0.1.0b1

The first beta adds GitHub App repository import and synchronization, a
production Compose example, and service-scoped container configuration.
This is a prerelease for broader testing, not a release candidate.

## Upgrade from alpha: fresh database required

Database migrations were reset to the current application structure, and the
legacy automations and integrations apps were removed. Existing alpha databases
cannot be upgraded in place with `migrate`. This release has no automated data
conversion path.

Stop SecondShift and back up the existing databases, private environment files,
and runner storage before upgrading. Keep the old version available if you need
to return to its data.

For an installed local build using the default data directory, move
`~/.secondshift` aside before starting the beta. It creates a fresh installation;
repositories, connections, approvals, and schedules must be configured again.
Use the corresponding directory if you configured a different data location.

For a server deployment with an existing alpha database, provision fresh
application and runner databases and initialize them using the deployment guide.
Preserve the old databases and storage until the new deployment is verified.

## Included

- GitHub App authorization, repository and branch selection, pinned source
  imports, and polling for changes. Source access is separate from job MCP
  permissions and GitHub sign-in.
- A single-server Docker Compose deployment with Caddy HTTPS, separate
  PostgreSQL application and runner databases, private S3 artifacts, and gVisor.
- Separate environment files for web, worker, gateway, and runner services.
- A workspace switcher that matches the dashboard, shows membership roles,
  and clearly marks the current workspace.

## Validation and limitations

Local integration checks cover fresh PostgreSQL migrations, private S3 artifact
uploads and reads through RustFS, and HTTPS through Caddy's local CA. Release
checks build and install the wheel in a clean environment and exercise sandbox
execution, reports, and webhook delivery with a simulated model provider.

Full production execution under gVisor still requires a target-host test. Verify
one complete GitHub import and job run, the production bucket's permissions,
public certificate issuance, and backup restoration before enabling schedules.
GitHub sync uses polling; bundles are limited to 64 MiB, and Git LFS objects and
submodule contents are not downloaded. The Compose example uses a single server
and updates have downtime.
