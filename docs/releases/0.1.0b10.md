# SecondShift 0.1.0b10

This beta lets runs start sub-agents and gives long jobs room to work. Jobs can
read files their earlier runs saved. Several run, delivery and connection
states are now reported more accurately.

## Sub-agents and long jobs

- A job can set `subagents: N`. Its agent can then hand a task to a fresh
  sub-agent and get a report back. Sub-agents use the run's approved tools and
  nothing more. They cannot start their own sub-agents, and their usage counts
  toward the run's limits. This works for the built-in agent and Claude Code
  subscription runs. Codex runs still start none. The server caps the number
  with `SECONDSHIFT_RUN_SUBAGENTS_MAX` (default 5). See
  [sub-agents](../repository-configuration.md#sub-agents).
- A job with `history: N` now also gets the files its last N successful runs
  saved. They are mounted read-only at `/history/<run id>/`, so a job can keep
  state such as a findings file between runs.
- Owners can raise one job's limits further without a server change. The
  defaults do not change. The new maximums are 2 hours, 200 turns, 500 tool
  calls and 20 million tokens. Operators can lower them with the `_CEILING`
  variables. See [run limits](../self-hosting.md#run-limits).
- Cached input counts as a tenth of a token toward a run's token budget. Runs
  still report every token as the provider reported it, so cost is unchanged.
- Each run's prompt states its limits and start time, so the agent can plan
  its work.
- Claude Code runs check the token budget as each reply arrives, instead of
  only at the end.
- A new weekly security audit example verifies its findings with sub-agents.

## Runs and deliveries

- Run status changes go through one set of rules. A run canceled mid-run can no
  longer be marked succeeded.
- A scheduled run whose access was lost fails at start with "The run could not
  start", instead of a sandbox error after a checkout.
- A job removed from `.secondshift.yaml` shows as removed and cannot be started
  by Run now, the API or a webhook. Adding it back clears the mark, and the job
  stays off until someone turns it on.
- A job's next run is recomputed when its schedule changes or it is turned back
  on.
- A delivery that failed and is about to be sent again shows as Retrying, with
  the reason from the last attempt.
- A webhook that arrives while the run queue is unavailable gets 503 with
  `Retry-After: 60`. The failed attempt does not count toward the hourly cap.
- When a custom MCP tool rejects a call, the model sees the tool's reason, with
  the connection token masked.
- A subscription run whose agent sandbox stopped says so, instead of asking you
  to check the login.

## Connections and dashboard

- An expired GitHub personal access token shows as expired everywhere,
  including the Overview count of connections to fix.
- Disconnecting or reconnecting an agent login works while the runner is down.
  SecondShift retries removing the runner's cached copy every minute, and the
  Models page shows when a copy is still held.
- GitHub and local repositories report sync state with the same rules.
- Repository pause controls are easier to find, and job schedule actions are
  clearer.
- Overview spend and the runs list are faster with long usage history.

## Upgrade from beta 9

Keep your data, private environment files and encryption keys. Install the new
wheel or pin `ghcr.io/piotrekno1/second-shift:0.1.0b10`, then follow the normal
[upgrade procedure](../production-deployment.md#update-and-back-up). This release
adds database migrations, which run as part of that procedure. Wait for
container publishing to finish before pulling the image. Beta releases do not
advance the stable `latest` tag.

Rebuild the separate subscription agent image from this release and update
`AGENT_IMAGE` to use it. The image adds the Claude Code sub-agent hook and the
new budget rules. Keep the old image until active runs finish. The application
release does not publish this image. See
[subscription setup](../production-deployment.md#optional-subscription-agents).

Installations that set the `_CEILING` variables explicitly keep those values.
Remove them if you want the new maximums.

For older alpha installations, follow the
[beta 1 upgrade instructions](0.1.0b1.md); fresh databases are still required.

## Validation scope

Automated tests use stand-ins for external services. Real subscription logins,
provider access, public HTTPS and production storage permissions require checks
on the target deployment. The release workflow builds and checks the wheel,
runs an installed-wheel smoke test, then publishes the prerelease and container.
