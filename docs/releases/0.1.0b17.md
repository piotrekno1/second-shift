# SecondShift 0.1.0b17

## Upgrade from beta 16

- Take a backup and follow the usual
  [update steps](../production-deployment.md#update-and-back-up). There are
  no new migrations and no Compose changes.
- If you use Claude Code or Codex logins, rebuild the agent image after
  `dc pull`, as the update steps say. The new image reports a run's progress
  while it works. An older image keeps working, but its runs show usage only
  when they finish.
- With `secondshift up` or a `pip` install, nothing changes for you.

## Run timeline and usage

- **Every tool call is on the timeline**, for model API runs and subscription
  logins alike: "Read src/app.py", "Searched src", "Ran pytest · exit 1",
  "Edited notes.md". A line names the file or the program, never a command's
  arguments, a search's text, a file's contents or a tool's output. A
  time-out shows as a warning.
- **Subscription runs show usage while they work.** The agent image sends
  Claude Code's turns, token usage and models every ten seconds, and the run
  page shows "9/24 turns" next to its tokens. A run whose container stops
  before it reports keeps the last counts it sent, instead of showing usage
  as unavailable. Codex reports usage only when it finishes, so its token
  budget still can't stop it partway.
- The run list shows each run's agent and model, such as "Claude Code ·
  claude-opus-5-5 +1", including for failed runs.

## New task

- **Tools** and **Delivery** are separate sections, and each shows what is
  chosen while closed.
- Each connection is one row, such as "2 of 20", that opens on demand, with
  a search across every connection's tools.
- Tools the skill needs start selected and show as chips you can remove. A
  repository skill needs what this repository's jobs request for the same
  skill. Nothing else is selected for you.

## Connections

- Access an MCP server grants beyond what was requested is one line,
  "Broader access than requested", with its scopes behind a click. Access
  granted at sign-in is shown in grey, since whoever signed in chose it.
- If a later token refresh grants more than the sign-in did, the line turns
  amber, "Granted more access since you connected", and marks the new scopes
  until someone reconnects. Before, a refresh widened the grant silently.
  Existing connections take their baseline at their next refresh.

## Settings

- **Settings → Runners** (staff only) shows each runner as a card: its state,
  sessions and limit, environments with the default marked, whether it can
  run Claude Code and Codex, and a shortened key you can copy.
- **Settings → Server** starts with the sandbox and ends with deployment
  details. Environments are no longer listed again per runner.

## Fixes

- Servers that keep artifacts in S3 now store a run's file changes and saved
  files. Since collection was added, every such run noted that they "could
  not be collected".
- The MCP recipes said a sign-in is refused when the server grants more than
  was ticked. It is refused when the server grants less.
