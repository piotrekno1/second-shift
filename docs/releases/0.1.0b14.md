# SecondShift 0.1.0b14

## Upgrade from beta 13

- No manual steps. The release has one new migration, `runs.0017`, which
  runs with the others when you upgrade.

## Explore

Explore is a new page in the sidebar. It lists skills you can run once on
your own code, then schedule if you like the result. See
[Explore skills](../explore.md).

- Each card says what the skill does, who publishes it, and what it can
  change: a patch for your code, or the services it uses and whether it
  writes to them. Filter by what a skill is for, such as **Code review**, or
  by a product it works with, such as **Sentry** or **Django**.
- A skill's panel shows what you get, an excerpt from a run the SecondShift
  team did when there is one, what it can change, how often it is worth
  running, and the repository, pinned commit and license. Its address can be
  shared.
- **Try it on a repository** opens the task form for that skill on a
  repository you choose. If the skill needs a service that isn't connected,
  the button asks you to connect it first, and **Back to skill** returns you.
  Adding a repository on the way also brings you back.
- **Try from a link** runs any `SKILL.md` on GitHub once, without adding it
  to Explore.
- The list ships with SecondShift and is never fetched, so Explore works on
  installs without internet access. Every skill is pinned to a commit, and
  listed skills must be under MIT, Apache-2.0, BSD, ISC or CC-BY-4.0.
- After the first run, Overview points to Explore with **Try a skill**.

To suggest a skill, open a pull request that adds it to the catalog file, or
open an issue. See [suggest a skill](../explore.md#suggest-a-skill).

## Schedule a skill you tried

When a try succeeds, the run page asks whether to keep the skill running.
**Schedule it** opens a dialog that builds the job: its name, when it runs,
and where results go. The job pins the commit the run used.

- On a GitHub repository where an owner allows pull requests, **Open pull
  request** adds the job to `.secondshift.yaml` on the default branch as a
  draft pull request. The rest of the file stays as it was. A job with the
  same name is never overwritten, and asking twice opens one pull request.
- Anywhere else, **Copy** gives you the job to commit yourself.
- The job starts once it is merged and the repository syncs. An owner still
  approves any services it uses.

## Smaller changes

- The repository page shows the synced commit next to the branch, linked to
  GitHub, and when it last synced.
- Overview says a job **Needs connection** before it says it needs approval,
  and refreshes while a new repository syncs.
- The Overview card for coding agents says what they can do: check
  `.secondshift.yaml` before you push, start jobs and read run reports.
- A failed task scrolls its error into view.

## Fixes

- An interrupted model stream now ends with an error event, so an SDK no
  longer takes a partial answer as complete.
- Model usage and the run's token budget are recorded together. A failed
  write no longer leaves usage the budget didn't count.
- A backlog in one repository no longer holds back due tasks in others.
- A delivery retry that ended without saving an outcome is now marked
  failed, so it can be retried again. Before, it stayed **Retrying** for good.
- Adding a repository saves its first sync request with it, so a crash in
  between can't leave it with no jobs.
- A repository removed while it was syncing stays removed.
- The repository page refreshes its jobs when a sync finishes between two
  polls.
- Repository and job lists no longer load each job's skill text, and MCP
  `list_jobs` plans jobs without extra queries per job.
