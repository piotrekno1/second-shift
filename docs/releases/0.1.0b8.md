# SecondShift 0.1.0b8

This beta can run jobs through a Claude Code or Codex subscription instead of
an API key. It adds one-off tasks, keeps the files a run changes or saves, and
can open draft pull requests. GitHub access now works with a fine-grained
personal access token, and new workspaces get a setup checklist.

## Claude Code and Codex subscriptions

- **Run jobs with a subscription.** Owners save a Claude Code or Codex login
  on **Models**. The CLI runs in a locked-down container with no shell, web
  search or other built-in tools. It reaches only the run's approved tools,
  through a run-scoped MCP endpoint (#177 to #182).
- **On by default in `secondshift up`.** The first start builds the agent image
  and takes a few minutes. Later starts use Docker's build cache.
  `secondshift up --no-agents` starts without subscriptions (#183, #184).
- **Run limit per login.** An owner can cap how many runs a login makes in a
  rolling 24 hours, so overnight jobs don't use up the day's allowance (#187).
- **Login checks.** A login is checked when it is saved. A run that fails with
  an expired sign-in checks the login again. Only a refused sign-in stops
  runs. A used-up allowance or a timeout does not (#196, #197).
- **Token usage.** Run lists and details show the usage the CLI reports. There
  is no dollar cost for subscription runs (#192).

Logins are encrypted at rest and never returned by the API. The login reaches
the runner sealed to its key, and never appears in container arguments,
environment variables or logs. See the
[agent subscriptions guide](https://github.com/piotrekno1/second-shift/blob/main/docs/agent-subscriptions.md).

## Models page

- **One place for what runs jobs.** API keys and subscription logins share the
  new **Models** page. The one in use is marked **Runs jobs**. Others offer
  **Use for jobs** or say why they can't (#190, #191).
- **Nothing changes on its own.** A new key or login is chosen only when
  nothing chosen can run jobs. A broken choice is never swapped for another
  key or login, so billing never moves without an owner (#179, #190).
- **Connections** now lists only what jobs ask for by name. **Settings** loses
  its "Run jobs with" panel.
- **Clearer refusals.** Run now and Enable say what is wrong, such as "The
  default model provider Anthropic has no model selected." Before, they always
  showed one fixed message. A provider with no model, or one that failed its
  last check, no longer starts runs that would fail (#175, #176).
- **Warnings cover every case.** The page warning now shows when nothing is
  set up yet, when a key is broken, and when a login is disconnected or at its
  run limit (#189).

## One-off tasks

- **New task.** On a repository page, write instructions or pick a committed
  skill. The task runs once on a pinned commit, without a saved job. The MCP
  server offers the same as `submit_task` (#193 to #195).
- **Queue and delay.** Tasks wait their turn, one at a time per repository. An
  optional start time delays a task without holding a worker. Queued tasks can
  be canceled from the dashboard, the API or MCP (#198).
- **Tasks guide.** A new guide covers written tasks, skills, tools, delivery,
  queue timing and MCP examples. The New task dialog links to it (#199).

`SECONDSHIFT_TASK_QUEUE_LIMIT` caps unfinished tasks per repository. The
default is 100. See the
[environment variables](https://github.com/piotrekno1/second-shift/blob/main/docs/environment-variables.md)
for the other queue settings.

## What a run leaves behind

- **Delivery records and retry.** The run page lists each notification with
  its status. A failed one can be retried. The stored report is sent again and
  the agent does not run again (#201).
- **Saved files.** The agent can save files in `/outputs`, such as CSV, JSON
  or images. The run page lists them for download. Notifications name them
  with their sizes, never their content (#202, #204).
- **Draft pull requests.** An owner can let a GitHub repository take draft
  pull requests. Then a task can ask for one, and a job can set
  `pull_request: true` in `.secondshift.yaml`. After the sandbox stops, the
  worker pushes `secondshift/run-<id>` and opens a draft. The commit carries
  `[skip ci]` unless the owner allows CI. A failed publish can be retried
  without running the agent again (#205 to #207, #209).

Only runs that open a draft pull request keep a patch of their changes.
SecondShift never asks for GitHub's `workflows` permission, so changes to
workflow files are refused by GitHub.

## GitHub

- **Personal access tokens.** A fine-grained token now works everywhere the
  GitHub App does: import, sync, autosync, draft pull requests and GitHub MCP.
  Connect one on **Repositories**. Its expiry is read from GitHub and shown on
  Connections (#210).
- **GitHub tools use the repository's connection.** No separate token is
  stored for GitHub MCP. Each call gets a token for one repository (#210).
- **Check access.** Each GitHub connection can check what sync, GitHub tools
  and draft pull requests can do. Each gap links to the GitHub page that fixes
  it. The worker checks once a day, and when a sync fails (#211).
- **One GitHub card.** Repository access, GitHub tools and sign-in show as one
  card on Connections (#211).

## Setup and local use

- **Setup checklist.** Until a job is on a schedule, Overview lists three
  steps: add your code, choose what runs jobs, turn on your first job (#211).
- **Repositories without a valid `.secondshift.yaml`.** Import no longer
  fails. The repository is saved with no jobs, and its page says what to fix.
  Autosync picks up the first valid config on its own (#188).
- **Quieter `secondshift up`.** Service logs go to rotating files in the data
  folder. New commands: `secondshift logs` and `secondshift status`.
  `--debug` prints logs in the terminal. A second instance on the same data is
  refused (#185, #186).
- **Separate workflow database for SQLite.** Durable workflows now use
  `workflows.sqlite3` in the data folder. Sharing one SQLite file could
  deadlock when a run was queued. PostgreSQL installs are unchanged (#208).

## Upgrade compatibility

From beta 7, keep your existing data, private configuration and encryption
keys. Install the new wheel or update the pinned container image to
`ghcr.io/piotrekno1/second-shift:0.1.0b8`. Then run the normal migration
commands. Upgrade the web app and workers together.

This release adds migrations. They copy each workspace's default model key to
the new choice of what runs jobs, and record a task for each past run. No
reset is needed.

**SQLite installs, including `secondshift up`:** to keep queued runs and their
workflow history, stop SecondShift and copy the database before you start the
new version. Skip this if `workflows.sqlite3` already exists.

```bash
cd ~/.secondshift && sqlite3 secondshift.sqlite3 ".backup workflows.sqlite3"
```

Without the copy, past runs and reports stay. Only workflows that were queued
or running at shutdown are lost. If you set `SECONDSHIFT_WORKFLOW_DATABASE_URL`,
it is used as before. It must point to a different file from the application
database.

**GitHub App permissions.** Sync still needs only **Contents: Read-only**. For
new features, add these permissions in the App settings, then accept them on
each installation:

- GitHub tools: **Pull requests**, **Actions** and **Commit statuses:
  Read-only**.
- Draft pull requests: **Contents** and **Pull requests: Read and write**.

Until then, those features fail with a message that names the missing
permission. **Check access** on Connections shows what is missing. See
[GitHub repository access](https://github.com/piotrekno1/second-shift/blob/main/docs/github-app.md).

**Subscriptions on a server.** No agent image is published yet, and the
production environment generator does not set the agent settings. A server
that wants subscriptions must build the agent image, pin it by digest and set
the settings by hand. See the subscriptions guide. Without them, servers keep
using model API keys as before.

**From older alpha builds, fresh databases are still required.** Follow the
[beta 1 upgrade instructions](https://github.com/piotrekno1/second-shift/blob/main/docs/releases/0.1.0b1.md).

## Limitations

The tests use stand-ins for GitHub, the model provider and S3. Subscription
runs were tested end to end with the real Claude Code CLI and a fake login,
not a working subscription. They have not been tested under gVisor. Draft pull
requests were tested with real git and a mocked GitHub API. Real GitHub.com
and model providers, public HTTPS certificates, and production S3 permissions
still need checking on your own deployment. See the
[deployment guide](https://github.com/piotrekno1/second-shift/blob/main/docs/production-deployment.md).
